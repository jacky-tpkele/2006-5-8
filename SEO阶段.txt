路由设计原则（不破坏现有收录）
================================================================================

✅ 安全扩展策略：

1. **新增路由层级，不修改现有**
   现有：/products/ac-mcb
   新增：/products/ac-mcb/tpkm7-63
   → 父级路由不变，子级自动继承

2. **动态路由已存在，直接填充内容**
   现有：/products/[slug]/page.tsx（已有但可能未使用）
   → 只需添加数据，不改路由结构

3. **新路由独立创建，不影响老页面**
   新增：/solutions/[scenario]
   新增：/guides/[guide]
   新增：/markets/[region]
   新增：/tools/[tool]
   → 完全新路径，零冲突

4. **博客路由已有动态支持**
   现有：/blog/[slug]/page.tsx
   → 直接发布内容，自动生成路由

5. **内链优化，提升老页面权重**
   → 所有新页面内链回核心产品页
   → 老页面自动获得更多内部链接

6. **sitemap.xml 自动更新**
   → Next.js 动态生成 sitemap
   → 新页面自动添加到索引


❌ 需要避免的操作：

✗ 不要修改现有路由路径
✗ 不要删除已收录的页面
✗ 不要改变 URL slug 格式
✗ 不要移动现有 page.tsx 位置
✗ 不要修改已有页面的 canonical URL

风险提示
================================================================================

⚠ 质量 > 数量
   → 不要为了页面数而堆砌低质量内容
   → 每页至少 500 字原创内容

⚠ 避免内容重复
   → 同类产品页面要差异化描述
   → 不要直接复制粘贴参数表

⚠ 避免关键词堆砌
   → 自然融入关键词（密度 1-2%）
   → 语句通顺优先

⚠ 避免孤立页面
   → 每个新页面至少 3 个内链
   → 确保从首页 3 次点击内可达

⚠ 避免技术错误
   → 每次发布前检查 404 错误
   → 测试移动端响应式
   → 验证 Schema markup
